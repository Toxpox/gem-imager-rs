== Installation Instructions

=== Windows

. Download the Windows installer.
. Double-click the installer.
. Follow the on-screen instructions.

After installation, launch the application from the Start Menu.

==== Windows Security Notes

[IMPORTANT]
====
Flashing images requires low-level access to removable storage devices.

On Windows:

* You may be prompted by User Account Control (UAC) to allow elevated permissions.
* Some antivirus or endpoint security software may temporarily flag disk-writing tools.

These prompts are expected and required for the imaging process. Always ensure you downloaded the
installer from an official T3 Gemstone source.
====

=== macOS

. Open the downloaded application or disk image.
. Drag *T3 Gemstone Imager* into the *Applications* folder.
. Launch it from *Applications* or Spotlight.

[NOTE]
====
macOS may ask for permission to access removable volumes the first time you run the application.
Granting this access is required to write images to SD cards.
====

=== Linux

==== Flatpak

The Flatpak build (app id `org.t3gemstone.imager`) is not published on Flathub yet, so it has to
be built from a checkout of this repository:

[source,shell]
----
make package-gui-flatpak
----

==== Snap

The Snap package is ideal for the Ubuntu family of Linux distributions.

[source,shell]
----
snap install gem-imager
----

[NOTE]
====
The snap package supports flashing SD cards only.

USB (DFU) flashing to the board's onboard eMMC is *not* available from the snap: strict
confinement gives the application no access to raw USB devices. Use the `.deb`, `.rpm` or
AppImage build if you need to write to eMMC.
====

==== AppImage

AppImage is useful if you prefer a portable, self-contained executable.

[source,shell]
----
chmod +x gem-imager-*.AppImage
./gem-imager-*.AppImage
----

==== AUR (Arch Linux)

On Arch Linux and its derivatives the package can be built from the AUR with any helper:

[source,shell]
----
paru -S gem-imager-gui-git   # or: yay -S gem-imager-gui-git
----

The command line tool is packaged separately as `gem-imager-cli-git`.

[NOTE]
====
These are `-git` packages: they build the current state of the `main` branch rather than a
tagged release, so a rebuild is what upgrades them.

The GUI package installs the `udev` rule needed for USB (DFU) flashing, so the manual step
below can be skipped.
====

==== Enable USB (DFU) Flashing Support (Optional)

If you are using Linux and need to write to the board's onboard eMMC over USB, your system will
require a custom `udev` rule to access the DFU interface without root privileges.

This step is **not** required if you are only flashing SD cards or USB storage. The `.deb`,
`.rpm` and AUR packages install this rule for you.

. Create a new `udev` rules file:
+
[source,shell]
----
sudo nano /etc/udev/rules.d/10-t3gemstone.rules
----

. Add the following lines to grant user-level access to the board in DFU mode:
+
[source,text]
----
include::example$10-t3gemstone.rules[]
----

. Reload the rules to apply the changes immediately:
+
[source,shell]
----
sudo udevadm control --reload-rules
sudo udevadm trigger
----
